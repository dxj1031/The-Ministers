局势图从已播放的发言重建阵营与关系，并直接融入原朝堂舞台：保留透视地板、猫皇、角色招牌动作、双方特写与诏令特效，不再通过独立手机舞台入口观看。实际游说时角色走近对象，回应后按已播放立场归队；转向时换位，连线分别表示同盟、拉拢、施压和已断裂同盟。简述气泡挂在当前发言角色上，点头像或群聊展开论据。

电脑布局使用完整窗口宽度（最高 1760px），不缩放 390px 手机画框；1440px 起采用词条与输入、朝堂、群聊三栏，较窄电脑窗口群聊置于朝堂下方。窄屏先排列词条墙与输入，再排列朝堂和群聊；通过 `?court=<id>` 可恢复已有朝会，默认暂停，不重新生成开场。

## 本地体验扩展：群辩、插话和词条墙

本节后端扩展仍在本地运行；对应前端界面已同步到线上，见上节发布记录。

- 猫皇拥有常驻输入框，可向全场或指定大臣追问、补充事实、提出约束。两位不同立场大臣即时回应，不消耗原定群辩轮次；插话前已生成的内容保留在实录，不冒充新回应。
- 大臣发言拆成主张、理由、引用材料。出处只能选择实际输入原文；缺依据时标为假设，缺失论证时明确可追问。未提供来源的新闻、旧事等说法会标记为待核实，不能把引用原文视为论证已经成立。
- 每轮两位对呛、另外两位加入群辩，再进行交涉及回应，至少四位不同参与者。模型依然一次生成一轮，由界面逐句呈现，并非多个模型并行发言。
- 交涉规则包含游说、同阵营结盟、对立阵营施压与拉拢背盟。同盟提供抵抗，重复交涉累积压力；背盟须先有同盟，成功后撤销旧关系。机制是角色游戏的启发式规则，不代表对论据质量的客观评判。
- 局势词条墙支持风险、机会、约束、事实四类，自由加入、切掉和恢复。生效词条进入材料，并强化关注该类问题的角色的交涉力度，最多叠加 0.3；切掉后不再参与后续计算，已经发生的变化不被回滚。
- 时间线记录行动双方、结果、前后立场、回应编号和词条影响；支持按大臣追踪。可展开查看影响力、累积压力、词条、同盟牵制和情境波动的判定说明。
- 暂停同时冻结台词、动画与局势。在途模型调用可完成，但结果只入待播队列；恢复保留当前句阅读时间，也可单步查看下一句。
- 数据采用增量迁移：旧朝会和旧发言保留，新增词条及发言详情字段。词条和机制事件可随本场记录导出。

验证：原有 court / store / library / eval 自检，新增 `tests/test_experience.py` 的确定性机制与 API 检查，以及 `tests/test_frontend.cjs` 的在途暂停、失效计时器、猫皇回应、词条切换和阵营轨迹检查。另以本机 qwen2.5:14b 检查真实发言与浏览器操作；模型仍可能论证薄弱或说法与角色不符，不能以接口成功代替内容质量验证。

## 目的 1：消解迎合感 · 已完成

**做法**：迎合不再是一条看不见的公式，而是一个看得见、将来可以罢免的角色。

| 步 | 内容 | commit |
| --- | --- | --- |
| 1 | `sycophancy_rate` 指标 + `--lean` 对照跑法 + 监控台两列 | `040ff3a` |
| 2 | 第十二位大臣「应声」，`lean` 撤出辩论引擎 | `4c8075a` |
| 3 | 裁决双句：判词由应声念，谏言引用终局反对方原话 | `5030486` |

**量出来的东西**：原以为污染来自倒戈阈值里的 `lean` 项，撤掉后迎合率一动不动。
真正的藏身处是强制站队那一行（`"pro" if lean >= 0 else "con"`），值 +2.6pp；
而且 `>= 0` 让 `lean=0` 也算赞成，连「中立」那条基线本身都是偏的。
第三处在回合 prompt 里（`皇帝倾向 lean=…`）—— 票型测不到，但十一张嘴都在顺着皇帝说话，
它是靠「`lean` 只能有一个消费者」这条约束逐行查出来的，不是靠指标发现的。

**门禁**：`test_lean_does_not_reach_debaters()` —— 把随机种子钉死，
三个 `lean` 必须跑出逐条相同的立场序列。离线基线 48.0% / 48.0% / 48.0% 是佐证，不是门禁
（倒戈种子里掺了 `uuid4`，换个 checkout 绝对值会飘）。

**已收尾**：名册页第十二行不编号、写明「只在裁决时开口」、头像描金边；演示朝堂里它栖在
御座旁边，辩论期间台词永远是「…」。M1.4 罢免做完：`decree(kind="dismiss")` 不可逆，
名册回到十一位，**判词换皇帝自己念**（没有谀臣了，判词就只是判词），不动 `lean`，谏言照旧。
代价真的发生，罢免才不只是一个按钮。

`stake` 职业发展与家庭期望 · `deadline` 三十五岁。

## 目的 3：第三方视角 · 进行中

**做法**：裁决之后不是一句判词，而是一面镜子：这次是哪几种偏见把你推过去的、
你忽略了谁、以及你的裁决是不是早在提交奏章之前就定了。

**已完成**：
- `court_session` 加 `lean_open` / `verdict_aligned` 两列，老库由 `store.LATE_COLUMNS` 补
- `lean_open` 只在 `create_session` 写一次，没有 setter —— 事后问拿到的是合理化，不是数据
- `_aligned()` 三种值：开场没倾向记 `NULL`（不是 0，否则把没表态的局当证据拉低确认率）；
  带着倾向却搁置或退朝记 0 —— 那正是「这次没被自己的倾向牵着走」
- `_mirror()`：推你过去的三位、你忽略的那位、跨局确认率，全部从 `turn` 表算，不调模型。
  「你忽略的」直接复用谏言（`_remonstrance`）—— 同一个判据算两遍迟早算出两个答案
- 奏章屏一个原生 `<input type="range">`（三档读数：偏驳回／尚无定见／偏准奏），开堂那一下送出去
- 裁决屏「🪞 朝堂镜」三行；这一屏改成可滚动（内容 890px > 容器 725px，原本会裁掉）

**M3.3 御笔批注**（已做）：计划写的是「从 localStorage 挪进 turn 表」，动手才发现
没有可挪的东西 —— 这个功能从来没做过，前端的 localStorage 只存了一个语言设置。
所以是把它建出来：批注记成皇帝的一行（`kind="note"`、`target` 指向被收藏的大臣），
不进评估分母；朝堂镜多一行「你总收藏谁」，少于 3 条返回 `None`（一两条是巧合，不是倾向）。

**顺带修掉一个一直没被发现的崩溃**：`liveView()` 的作用域里从来没有 i18n 字典 `t`，
而 M1.3 以来我在那里写了 `t.logStance` / `t.mindByUser`。离线演示走不到那几行，
所以一直没暴露 —— 第一次在浏览器里真跑一局，整个渲染直接 ReferenceError。
现在 `t` 显式传进 `liveView(t)`。**这说明只验演示数据不够，真路径得真跑一遍。**

**验收**：确认率本身就是指标。长期稳定在 100% 说明产品是一台盖章机 ——
这个数字不需要优化到某个值，它需要被用户看见。
