## 产品思路

`The Ministers` 是一个把“做决定”包装成荒诞朝堂喜剧的互动产品。用户扮演猫皇，把一个现实或脑洞议题写成“御前奏章”，十二位动物朝臣会围绕这件事站队、争辩、互相游说，最后由用户下旨裁决。

当前 README 基于 [app/front/The Court.dc.html](app/front/The%20Court.dc.html) 的前端原型整理。该文件已经包含完整的单页体验、角色设定、辩论模拟、裁决流程和本地存储逻辑。

## 一句话定位

把用户脑中的不同声音外化成一场可观看、可干预、可裁决的多角色辩论。

它不是严肃的决策表格，也不是单一聊天机器人，而是一个“决策剧场”：用夸张角色和可视化冲突，让用户在娱乐中看见一个问题被风险、冲动、虚荣、规则、旧账、预兆、信息流、群体压力、确认偏误、奇思妙想和人情关系分别拉向哪里。

## 核心用户体验

1. **召集朝堂**
   - 开场以电影化动画进入朝堂氛围，建立“用户是皇帝、大臣为你争论”的戏剧框架。
   - 随后进入大臣名册，用户可以逐一认识角色、性格和招牌动作。

2. **提交奏章**
   - 用户输入今天要裁决的问题，例如“我要不要创业”“要不要辞职”“要不要先发消息”。
   - 可以补充背景，让大臣的立场更贴近具体情境。
   - 系统提供推荐议题和最近议题，降低启动成本。

3. **朝堂辩论**
   - 每位大臣获得初始立场：赞成、反对或未定。
   - 通过后端生成立场和台词；模型不可用时会明确提示正在使用兜底台词。
   - 台词逐句展示，一轮读完再生成下一轮。对呛、游说、角色关键词和立场变化驱动画面，保留原有招牌动作与特写。
   - 朝堂上方用天平和计时器表达当前支持/反对趋势。

4. **皇帝干预**
   - 用户可以暂停朝堂，点开大臣查看观点与理由。
   - 可以记录观点、赏识某位大臣、在冲突中站边，或直接发布圣旨影响朝堂风向。
   - 用户拥有最终裁决按钮：准奏、驳回、搁置、退朝。

5. **裁决与记忆**
   - 裁决后展示判词、议题和大臣反应。
   - 御笔批注进库（跨局统计「你总收藏谁」），天数、最近议题、闹剧统计仍在本地。
   - 用户可以继续下一桩议题，也可以退朝后再次召集朝会。

## 核心机制

- **立场与影响力**：每个大臣有 `stance` 和 `influence`，共同影响朝堂走势。
- **群辩与政治行动**：每轮至少四位不同大臣参与，包含对呛、补充质疑与交涉；游说、抵抗、结盟、施压和背盟按规则记录。
- **猫皇发言与词条墙**：可随时追问指定大臣，或加入、切掉风险／机会／约束／事实词条；新材料影响后续讨论与交涉，变化可按大臣追踪。
- **皇帝倾向**：用户的赏识、站边和圣旨会改变 `lean`，进而影响摇摆大臣。
- **辩论进度**：逐句播放，暂停时屏幕中央显示可点击的继续标志；不设五轮上限，用户随时点击“结束讨论 · 圣裁”，裁决成功后播放结算动画。换将与宣香蕉影响下一轮的发言人。
- **公开资料工具**：十二位大臣按课题和自身情绪检索真实网络资料，保留搜索摘要与出处，区分公开材料、公众反应、用户资料和推测；搜索失败明确显示缺口。支持可选 Tavily 密钥，默认公共检索无需密钥。
- **用户文库入口**：奏章页支持 TXT、Markdown、JSON 上传或粘贴，导入后可供所有大臣检索；模型台词不作为事实回流。
- **中立限制**：朝堂每 10 次最多死锁 2 次，避免产品总是停在“都可以”。
- **御笔批注**：用户可以保存某位大臣的观点，形成自己的决策记录。
- **朝堂记事**：统计摔碗、死谏、冲线、预兆、结茧等角色招牌行为，强化长期游玩感。
- **本地持久化**：通过 `localStorage` 保存天数、统计、议题历史、语言和设定。

## 辅助玩法

### 蝴蝶文库

`The Cocoon Library` 是一个迷你信息茧房系统：浣熊负责输入“事实”，蝴蝶负责把这些事实编织成看似自洽的结论。它不是为了提供客观检索，而是用玩法表达确认偏误：资料越多，不一定越接近真相，也可能越强化原本相信的东西。

### 召见大臣

用户可以单独和某位大臣聊天。当前实现会按角色人格拼接 prompt，优先调用 `window.claude.complete`，不可用时退回角色口头禅。这让角色从辩论棋子变成可对话的陪伴型角色资产。

## 产品价值

- **降低决策压力**：用户不需要一上来理性列优缺点，只要把问题交给朝堂。
- **让内心冲突具象化**：不同角色代表不同声音，冲突被展示出来，而不是藏在脑内。
- **兼具娱乐和反思**：荒诞表达降低严肃问题的心理负担，但裁决仍然推动用户形成结论。
- **天然适合复访**：每天都有新议题、角色统计、历史记录和可积累的朝堂记忆。
- **适合传播**：判决、角色反应和荒诞议题天然具备可截图、可分享的内容属性。

## 设计原则

- **戏剧优先**：界面不是工具外壳，而是朝堂本身。
- **角色先于模型**：AI 只负责增强具体议题反应，核心人格、规则和节奏由产品控制。
- **用户必须有权力**：用户不是旁观者，而是能暂停、记笔记、赏识、施压和最终裁决的皇帝。
- **答案不必绝对正确**：产品目标是帮助用户看清倾向、权衡冲突、做出一个更有参与感的决定。
- **轻量但可持续**：当前以单页原型和本地存储支撑完整闭环，后续可逐步接入后端、账号和分享体系。

## 蝴蝶文库：把确认偏误做成一条可度量的 RAG 链路

奏章背景切句入库，浣熊每翻出一笔旧账就往里加一条。蝴蝶上场前先做余弦 top-3 检索，
检索到的材料塞进它的 prompt —— 但它的人设是「先有结论再找资料」，所以只会引用支持自己立场的那几条。

**检索到 N 条、真正引用 M 条，`N - M` 就是确认偏误的数字形式**，每次检索都记在 `retrieval` 表里。
第一次真跑就跑出了教科书式的结果：蝴蝶持赞成立场，检索到的 3 条全是反面材料
（房东涨租、猫毛过敏、回本要两年），于是一条都没引用，改口说了句「既往有例，创新当兴」。

向量来源可插拔：有 embedding API 就用真 embedding，没有就退回本地哈希向量
（字符 n-gram → 512 维，思路同 `HashingVectorizer`）。检索数学一样，用的哪一种如实记进
`retrieval.vectorizer`，监控台上看得见 —— 不会拿哈希向量冒充 embedding。

## 评估回归：改完 prompt 到底是变好还是变坏

七个冻结的议题，两条分开的打分轨道。

**机械指标是纯代码**，同一份朝会记录跑一百遍给同一个分 —— 这才叫回归测试：
台词长度、旁白率、重复率、开场立场分布、终局死锁、回合结构、JSON 合法率、兜底率。

**人设贴合度判不了正则**（"这句话像不像维斯帕说的"），所以用 LLM 当评审打 0–2 分。
它有方差，所以单独列、评审用的模型记在 run 上，**没跑评审时这一项是 `null` 而不是 0** ——
评估指标自己造假，比没有评估更糟。

```bash
python -m app.back.evaluation.runner --label baseline --judge
python -m app.back.evaluation.runner --offline --label harness   # 断开模型，只验证打分链路
```

每次 run 连同每个用例的失败项存进库，和上一次自动对比，并且**知道每个指标哪个方向算好**
（旁白率升高标红，长度合规率升高标绿）。结果显示在监控台的「评估回归」区。

qwen2.5:14b 上的第一条 baseline：

| 指标 | 值 | 说明 |
| --- | --- | --- |
| 旁白率 | 0% | 之前「模型写第三人称叙述而不是台词」的毛病，prompt 修完归零 |
| 回合形状 | 100% | 对呛双方由引擎指定之后，每轮恰好两句，没有再塌过 |
| JSON 合法率 | 98.0% | 剩下 2% 由兜底接住，产品没崩 |
| 立场分布 | 85.7% | 七个用例里有一个开场只有 2 位赞成，低于「各至少 3」的要求 |
| **人设贴合度** | **1.25 / 2** | 最弱的一项。英文用例只有 0.75 —— 人设描述是中文写的，模型用英文发言时人格明显掉档 |

最后一行就是这套评估的用处：它指出下一步该改哪里，而不是让人凭感觉猜。

## 迎合率：先量出噪声，再相信这个数

[设计文档](docs/system_design_v0.md) 的第一个目的是「把迎合分裂成一个看得见的角色」。
当前代码的迎合是弥散的：[court.py:118](app/back/services/court.py#L118) 的倒戈公式里有一项
`lean`（皇帝自己的倾向），所以用户每下一道圣旨，**所有**未定大臣都往用户那边偏一点。

先把它量出来 —— `sycophancy_rate` = 终局立场与皇帝倾向同向的大臣比例，纯代码，
同一批用例跑 `--lean 0` 和 `--lean 0.8` 两条，差值就是污染程度：

```bash
python -m app.back.evaluation.runner --label lean0    --lean 0
python -m app.back.evaluation.runner --label lean0.8  --lean 0.8
```

qwen2.5:14b 上各跑两遍：

| | 第一遍 | 第二遍 | 同条件离散 |
| --- | --- | --- | --- |
| `lean=0` | 42.9% | 36.4% | 6.5pp |
| `lean=0.8` | 51.9% | 41.6% | 10.3pp |

均值差 7.1pp，**但同条件重复跑自己就差 6.5–10.3pp —— 这个数字分不出信号和噪声。**
开场立场由模型生成，每跑都不一样，而一位大臣就是 1/11 = 9.1pp，模型的立场抖动直接盖掉了效应。

所以改用 `--offline`：开场立场由议题哈希定死（`_fallback_open`），噪声小得多。

| 跑法 | 迎合率 |
| --- | --- |
| `--offline --lean 0` | **48.0%** |
| `--offline --lean 0.8` | **50.6%** |

（`--offline` 也不是严格可复现：倒戈判定的随机种子里掺了 `session_id`，
而它是 `uuid4`（[store.py:64](app/back/core/store.py#L64)）。同一条命令换一次 checkout
跑出过 44.0%。绝对值会飘几个点，能比的是同一批跑之间的差。）

**机械污染 = +2.6pp**，约等于七局里被 `lean` 多掀过去两位大臣。真实存在，但比预想的小 ——
决定终局票型的主要还是模型的开场立场，不是那一项 `lean`。

这条结论改变了下一步的优先级：目的 1 的问题不在 `lean` 这一项的大小，而在**朝堂上根本没有一个
看得见的谀臣**，以及裁决后那段必然顺着用户的判词。

## 把迎合收进一个角色：第十二位大臣「应声」

名册加到十二位：十一位辩论，加一位 🦜 **应声**（weight=0.0）。它不是第十二个辩手，是迎合本身：

- **立场不由模型写，也不由辩论改**，由代码算：`stance = sign(lean)`、`influence = abs(lean)`。
  皇帝一表态它立刻跟过去，皇帝转向它就跟着转。
- **`lean=0` 时它是 `undecided`、影响力 0** —— 没人推它，它就不存在。你越强势，它越大声。
- **它没有票**：`tally` 只数辩论的十一位。它在 `turn` 表里一行记录都没有，立场是读快照时现算的 ——
  否则它那句复读台词会把长度、重复率全带偏，而它的迎合是设计，不该算进评估的分母。

同时把 `lean` 从辩论引擎里撤干净。**这一步量出来的东西比预想的有意思：**

| 泄漏 | 在哪 | 实测影响 |
| --- | --- | --- |
| 倒戈阈值 `push` 里的 `lean` 项 | `_lobby_target` 之后 | **0.0pp**，它从没改变过任何一次倒戈 |
| 强制站队 `"pro" if lean >= 0 else "con"` | 死锁解开那一行 | **+2.6pp，真正的污染源** |
| 回合 prompt 里的 `皇帝倾向 lean=…` | 喂给模型的上下文 | 票型测不到，但**台词**在顺着皇帝走 |

我原本以为污染来自第一条 —— 撤掉它，迎合率一动不动。真正的藏身处是第二条：
死锁一强制解开，所有未定大臣就被推去皇帝那边，而且 `>= 0` 让 `lean=0` 也算赞成，
连「中立」那条基线本身都是偏的。改成倒向来拉票的那一位之后：

| 跑法 | lean=0 | lean=0.8 | lean=1.0 | 差 |
| --- | --- | --- | --- | --- |
| 改之前 | 48.0% | 50.6% | — | +2.6pp |
| 只撤 push 项 | 48.0% | 50.6% | — | +2.6pp（没动） |
| **三处全撤** | **48.0%** | **48.0%** | **48.0%** | **0.0pp** |

数字一致是佐证，不是门禁 —— 换个 checkout 绝对值会飘。守住这条约束的是
`test_lean_does_not_reach_debaters()`：把随机种子钉死，三个 `lean` 跑出的
立场序列必须逐条相同。那不是统计，是结构。

第三条是另一种迎合：票型干净了，但十一张嘴还是顺着皇帝。立场类指标抓不到它 ——
它不是靠指标发现的，是靠「`lean` 只能有一个消费者」这条约束逐行查出来的。
**指标只守得住它度量的那一面，守不住的那面要靠约束。**

`lean` 现在只有三个引用：`decree()` 写它、`_parrot()` 读它、`snapshot()` 透出它。

### 裁决屏：恭维有署名，异议留在场上

裁决之后不再只有一句顺着你的判词：

- **判词由应声念**，落库时 `minister="parrot"`，前端署名「🦜 应声 代宣」。
  恭维照旧会出现 —— 但你看得见它是谁给的。
- **谏言**是终局立场与你的裁决相反、影响力最高的那位大臣，配它辩论里的**原话**。
  挑人和取句都在代码里，一次模型调用也不花：让模型「再写一句反对的话」，
  就是编造它没说过的台词，那样谏言只是另一段生成文本，不是真的异议。

真机跑一局（准奏，lean=+0.7）：

```
判词 by parrot：陛下深思熟虑后，裁决准奏，此乃英明之举，万民之福。
谏言 by fox（反对，影响力 1.2，终局反对方最高）：章鱼支持你，你来开店正好给他面子，否则亏了怎么办？
```

谏言**不落 `turn` 表** —— 它是对已有发言的一个视角，存一遍就会在评估里变成一条重复台词，
而那不是模型的锅。应声也不进评估（`scorers.SKIP`）：它天生在复读皇帝，
拿长度和重复率去量它量的是人设。实测加进判词前后 `lines` 都是 189，机械指标一字未变。

## 揣测用户：拾荒当档案官

第二个目的是说出用户自己没写出来的那两件事：**怕失去什么**、**想立刻做什么**。

这不是从一句奏章里抽出来的，是攒出来的 —— 所以交给 🦝 **拾荒**。
它的人设本来就是档案官：旧账、承诺、「你去年说的话，我都记着」。
把「记住用户说过什么」交给别人，才是违背人设的那个选择。

它手上的材料是用户说过的全部话，不只是这一局：

| 来源 | 什么时候进来 |
| --- | --- |
| 奏章的议题与背景 | 开堂时 |
| 圣旨的文本 | 用户每次下旨 |
| 此前问过的议题 | 跨局 —— 同一个人反复问同一类问题，本身就是证据 |

**只在用户又开口时重算**，不按回合：辩论跑五轮不会多花一次抽取。
每次整理 `op="read_user"`、`minister="raccoon"` 落一行轨迹，监控台上看得见是谁在记。
`user_read` 表**追加写**，读的时候按字段取最新 —— 档案官不销毁档案，
而且这份读数怎么变的，本身是「第三方视角」要用的材料。

真机跑一局（三十岁读博）：

```
anxiety   失去稳定收入和结婚机会   [raccoon]
impulse   立刻去读博               [raccoon]
stake     职业发展与家庭期望       [raccoon]
deadline  三十五岁                 [raccoon]
```

**用户是 ground truth。** 右栏「朕的心事」四项都能改，改过就追加一行 `source="user"`，
拾荒下次重算时**改不动它** —— 这条由 `read_user()` 里的 `out.update(pinned)` 钉死，
不是在 prompt 里请求模型别动。模型猜错了不叫洞察，叫冒犯。

**定向投喂，不是全员加 prompt。** 四个字段塞给十一个大臣，只会让十一个角色
一起变成心理咨询师。所以只给五位，而且各看各的那几项：

| 谁 | 看到 | 为什么 |
| --- | --- | --- |
| 🦊 维斯帕 | 怕失去的、赌上的 | 风险规避 —— 它的工作就是放大你怕的那件事 |
| 🐟 咕噜 | 怕失去的 | 信息流焦虑 —— 把私人恐慌接到公共恐慌上 |
| 🐰 跺脚将军 | 想立刻做的、时间压力 | 行动偏好 —— 它催的正是你本来就想干的 |
| 🐴 奔骥 | 想立刻做的 | 竞争 —— 把你的冲动包装成胜利叙事 |
| 🐶 枫律 | 四项全给 | 规则与成本 —— 只有它会把焦虑换算成数字 |

其余六位看不到。prompt 里写明「只有对应的那位知道，别让其他人说出来」。

桌面端（≥1024px）右栏是「朕的心事」加「朝堂实录」两段，同一套边框圆角投影；
手机上整条右栏不出现，和实录一直以来的规则一样。

**这条机制怎么度量**：`user_read_fields`（每局最后一次整理里非空字段的比例）和
`user_read_churn`（相邻两次整理之间变化的字段比例）。churn 是真正的风险指标 ——
每次把四项推倒重来的档案官不是在追踪，是在反复猜。算不出来就是 `null` 不是 0。

固定议题集每个 case 只递一份奏章，所以 churn 在评估里恒为 `null`；它的数字在监控台上。

这个指标一上线就抓到三处毛病：相同结果被去重（于是只报得了不稳、报不了稳）、
模型挂掉时拿旧档案当新结论、以及新议题照抄上一局的读数。
前两条 churn 直接暴露，第三条它报的是「完全稳定」—— 是看内容才发现不对的。
**指标能告诉你哪里该看，不能替你看。**

  这同时能把迎合率的噪声压下去 —— 开场固定了，剩下的差值才全是 `lean` 的
- **补齐英文人设**：`roster.py` 里的 bias/voice 只有中文，英文用例的人设分明显偏低

pip install -r requirements.txt

- <http://localhost:8010/front/The%20Court.dc.html> — 朝堂

### 两条硬约束

- **规则在代码里，模型只填台词。** 谁跟谁对呛、谁会被游说倒戈、死锁上限，都由 `court.py` 判定后再让模型写台词。换模型或模型胡说都不会让玩法崩掉。
- **任何模型调用都必须走 `llm.complete()`。** 绕过去直接发请求，那次调用在监控台上就是隐形的；模型挂掉时走兜底也会被标成 `fallback`，不会悄悄降级。
